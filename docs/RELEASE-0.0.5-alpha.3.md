## DeziroJoy v0.0.5-alpha.3

本版是 SDL3 统一输入后端的第三个 alpha：Windows 更新改由外部 watchdog 接管安装并留下
进度与失败日志；映射界面两处手感修复；SDL3 增加普通 Joystick 的**映射补充流程**；
**U1 通用控件面板与按键捕获定位、U2 输入显示策略与通用方向语义完成实现**（均有自动化
测试，真机待复验）。默认输入后端仍为 XInput／evdev，SDL3 仍是设置中的显式实验选项；
S3 默认切换未开始。

alpha.2 的修复（SDL 每 tick 状态刷新、evdev 异步扫描、保守旧配置迁移、Windows 全局
键盘捕获、劫持直达、X11 EWMH 置顶、Game Bar 两层分离）在本版继续有效，详见
[0.0.5-alpha.2 发布说明](https://github.com/qiyuanhuakai/dezirojoy/blob/v0.0.5-alpha.2/docs/RELEASE-0.0.5-alpha.2.md)，此处不再重复。

### 本版更新

#### Windows 更新：外部 watchdog + 安装进度与失败日志

- **安装交给外部 watchdog**：一个临时的 Windows PowerShell 脚本（`System32` 下的
  `powershell.exe`，不加载安装目录任何 DLL、不常驻、结束即退）在安装前被启动，
  **比 GUI 活得更久**：等旧 GUI 退出（90 秒预算）→ 以 `/SILENT` 运行 Inno 安装程序
  （**显示安装进度窗口**，而非无反馈的 `/VERYSILENT`；`/NORESTART` 不自行重启）→
  读退出码 → 成功后启动已安装的 `DeziroJoy.exe`（并等 3 秒确认未被单实例仲裁打掉）。
- **为什么改**：alpha.2 及更早的流程里，GUI 等待安装程序会一直持有自身 `DeziroJoy.exe`
  与相邻库的句柄，安装程序的 DeleteFile 以拒绝访问（错误 5）回滚；重启也曾与安装
  程序自带的重启项竞争单实例租约——用户看到的就是“应用关了，什么都没发生，没有任何
  提示”。watchdog 两者都解决：先等旧进程消失再装，重启只由 watchdog 在确认退出码 0
  之后执行（安装程序不再自带重启项，更新永远不会启动两个实例）。
- **失败留痕**：watchdog 日志与 Inno 安装日志（`/LOG`）写在
  `%LOCALAPPDATA%\DeziroJoy\UpdateLogs\`（脚本、`dezirojoy-update-*.log`、
  `dezirojoy-setup-*.log`，运行后保留，便于用户反馈时一并发送）；安装失败、包缺失、
  超时（900 秒挂起检测）、守护进程自身异常时**写入并打开诊断日志**，并尽力把现有
  版本重新拉起来（daemon 已停止，用户不该面对没有应用的桌面）。安装目录从安装程序
  写进卸载键的 `InstallLocation` 解析，而非从当前进程猜测。
- **含空格的路径不断链**：`/LOG` 与 `/DIR` 的值由脚本自己带上双引号。Windows
  PowerShell 5.1 的 `Start-Process -ArgumentList` 只用空格拼接数组元素、不替含空格的
  值加引号，而默认安装目录与日志目录都在含空格的用户配置文件路径下
  （`C:\Users\John Doe\AppData\Local\DeziroJoy\...`）；不加引号时安装程序只会看到
  `/LOG=C:\Users\John`，日志被截断写到没人看的地方。
- **界面如实**：安装点击前，设置卡用「安装前说明」把整个序列（停 daemon 与托盘、
  关闭、安装程序显示进度并自动重启、失败在哪看）讲清——Windows 安装一旦开始本程序
  即将关闭，之后再没有窗口读这些信息；安装阶段的进度条为不确定态（“仍在进行”而不是
  假装百分比），最后一行说明安装程序接管进度并重启。

#### 精准面板与 SpecialKeyTarget 一致

- 精准面板现在报告**配置真正携带的精准键**（引擎读取的是 SpecialKeyTarget 精准键，
  鼠标映射自带的精准字段只用于旧配置迁移且迁移后保持默认）——此前面板只读字段，
  会在引擎实际跑特殊键时显示默认值。面板仍只是**展示**：改键在映射界面完成。

#### 编辑时手柄模型 0.65 缩放

- 编辑器打开时手柄模型缩放到 **0.65**（均匀、居中，与既有上移动画组合为同一渲染
  变换组，命中测试随矩阵走、每个键仍可点）；关闭编辑器恢复 1，无残留。

#### DInput 普通 Joystick 的映射补充（S1／S2 补充）

SDL3 能识别为标准 Gamepad 的设备走同一通用读取路径；只能作普通 Joystick 枚举、没有
可靠 SDL Gamepad 映射的设备（典型为 DInput 时代的手柄）此前不在支持声明内。本版
补上取证式映射流程，仍不维护型号白名单、不猜布局：

- **探针 `joysticks`**：只列出缺少标准 Gamepad 映射的普通 Joystick——GUID、名称、
  路径、VID／PID、原始按键／轴／方向帽计数（写映射的依据）；已有标准映射的设备单独
  计数，“没有要映射的”与“SDL 什么也没看到”因此不会混淆。同时打印当前映射文件。
- **探针 `map`**：对其中一台设备**逐键取证**生成标准 SDL 映射——依次提示 21 个必需
  项（面键四枚、十字键四向、start／back／guide、左右肩键、左右摇杆点击、左右摇杆
  X／Y、左右扳机）与 6 个可选项（截屏／分享、背键 1–4、触摸板）；`s` 跳过（设备
  没有该项）、`q` 取消；每项先取基线，已按住的控件不会重复捕获；约 60 Hz 采样且每次
  采样前泵一次 SDL；扳机与轴式十字键按半轴 `+aN`／`-aN`、摇杆轴按 `aN`、仅在反向时
  加 `~` 生成；**先本地校验再交给 `SDL_AddGamepadMapping`，被拒绝的映射不写入文件**；
  保存前明确列出跳过了哪些项（跳过的必需项结尾再次点名）——映射是不完整但诚实的
  描述，不把设备伪装成已有完整标准布局；同一 GUID 重复映射是更新而非追加；写入原子。
- **`sdl-mappings.json`**：配置根目录（Windows `%APPDATA%\DeziroJoy\`、Linux
  `~/.config/DeziroJoy/`），与 `input-backend.json` 同处 profiles 目录之外；条目为
  guid／name／mapping／updatedUtc，mapping 即 `SDL_AddGamepadMapping` 接受的文本，
  可手编；文件损坏或不可读时**宁可不映射也不覆盖**——本次运行只使用 SDL 内置映射库，
  扫描诊断给出 `持久 SDL 映射文件（sdl-mappings.json）读取失败：…`。
- **首次枚举前加载、重启后生效**：provider 在 SDL 初始化成功后、第一次
  `SDL_GetGamepads` 之前逐条 `SDL_AddGamepadMapping`——SDL 在构建手柄列表时就决定
  一个 Joystick 是不是标准 Gamepad，映射加晚了要等下次枚举。daemon 与探针读同一
  文件；**没有热切换**：daemon 只在启动时读一次（这也是 SDL 自身行为——按实例 ID
  的“是不是 Gamepad”结论在进程生命周期内不因新增映射失效），因此 map 保存后
  **重启常驻服务**生效。

#### U1：通用控件面板与按键捕获定位（已实现，真机待复验）

- **数据驱动的通用控件面板**：控件由设备的输入描述按五个固定分区生成（方向输入、主按钮、
  肩键／扳机、功能键、扩展键），不按型号绘图、不建立型号库；没有输入描述的后端仍回退
  既有手绘模型。未知型号接入只是多一组输入数据，不附带美术工作。
- **按哪个，就配置哪个**：劫持开启时新按下的按键直达该输入的映射配置并滚入可见；编辑器
  的按钮捕获带**设备隔离**——被捕获设备的映射分发暂停（按到正在配置的键不会触发它绑定的
  动作），但继续采样并上送样本供高亮与导航，其他设备映射不受影响，显式输出（文本／
  点按）仍照常；捕获开始与结束都会释放该设备已保持的输出，捕获期间一直按住的键不会在
  结束后的第一 tick 形成假按下沿。
- **捕获可靠结束**：超时（默认 15 秒并提示）、取消、断连、编辑器关闭均会结束捕获并卸载
  全局钩子。
- 以上均有自动化测试；**真实未知型号设备的复验待补**（现有真机证据仅限用户实测的
  Xbox／NS 全部按键可用）。

#### U2：输入显示策略与通用方向语义（已实现，真机待复验）

- **已绑定常显**：有映射的控件始终在面板上，且拒绝隐藏——用户做的配置必须可达。
- **检测锁存**：实际检测到过输入的控件显示并可高亮；锁存是**单向的**——松手或后续快照
  不再列出都不会把它退回“更多输入”，“尚未检测到”不等于“设备没有”。
- **声明更多输入**：SDL 已声明但未绑定、未检测到的控件收在“更多输入”折叠区，按固定顺序
  排列，可“显示全部输入／收起更多输入”。
- **用户隐藏与恢复**：可把控件从常用视图隐藏（只改显示，不动绑定、不改执行），并可一键
  恢复。
- **固定顺序**：分区内顺序恒为声明顺序；检测与隐藏都不会重排布局（增量分桶，高亮画在
  用户正在看的卡片上）。
- **方向外观与执行分离**：摇杆的**外观**（摇杆示意／十字示意）只改变外观；**执行**
  （连续轴／四方向触发）由用户显式选择并改写映射（被拒绝时选择器回退）。没有任何设备
  形态或轴沿行为会自动切换模式。
- 以上均有自动化测试；**真机复验待补**（少按键设备观感、隐藏／恢复、显示全部在真实
  设备上的表现）。

### 已知限制与验收边界

- SDL3 仍是显式实验选项：默认后端与 0.0.2 一致，provider 与探针未经完整真机验收；
  覆盖声明按 SDL 版本和能力记录，Xbox／NS 的有限证据不外推为全部设备已实测。
- 映射补充流程是 **S1／S2 的补充**：它让普通 Joystick 有机会进入同一读取路径，
  只覆盖用户实际映射过的设备，不代表全部 DInput 设备已支持。
- U1／U2 已实现（自动化测试），但**真实未知型号设备与真机场景待复验**；其验收不计入
  S2 完成。S2 验收未完成（旧配置迁移与映射补充的真机／多设备证据、Joy-Con 规则、
  同型号多设备、完整生命周期待补），S3（默认切换）未实施。
- 旧配置保守迁移（alpha.2）不变：只搬预设槽、一对一且无反证、marker 防重复复制；
  多设备与真实旧配置组合的真机证据待补。
- 后端切换与映射生效都需要重启（daemon 启动时读取），没有运行中热切换。
- Game Bar 两层均不保证抑制所有弹窗（实测部分 Win11 LTSC 仍可能弹窗）。
- 应用内自动更新按语义版本提供最新发布（含预发布）；`0.0.2-beta.3` 及更早版本
  的自动更新缺陷不变，从那些版本升级请手动下载。

### 升级与回退

- 升级不改变配置位置，不改写旧后端配置；未启用 SDL3 时默认后端不变
  （Windows 仍为 XInput，Linux 仍为 evdev）。
- 已启用 SDL3 的用户：升级后首次连接按 alpha.2 保守规则迁移（不切 SDL3 不发生
  迁移；已有 SDL3 自定义槽不被覆盖）；映射文件 `sdl-mappings.json` 原样保留。
- 回退：设置里切回平台默认后端，或重新安装 0.0.2；配置均保留。
- 完整说明见 [docs/SDL3-BACKEND.md](https://github.com/qiyuanhuakai/dezirojoy/blob/v0.0.5-alpha.3/docs/SDL3-BACKEND.md)。

## DeziroJoy v0.0.5-alpha.2

本版是 SDL3 统一输入后端的第二个 alpha，聚焦**手感、迁移与四处 Windows／Linux
细节修复**。默认输入后端仍为 XInput／evdev，SDL3 仍是设置中的显式实验选项；S3
默认切换未开始，SDL3 provider 未经真机验收。

相对 0.0.5-alpha.1 的变化：

### 本版更新

#### SDL3 输入刷新修复（不跟手）

- **每个 tick 刷新 SDL 状态**：provider 此前只在扫描 tick（默认 250 ms，约 4 Hz）
  调用 `SDL_UpdateGamepads`，`SDL_GetGamepadButton`/`Axis` 读到的一直是上次泵入的
  快照——动画与操作延迟即来源于此。现在枚举与诊断仍按 250 ms 节流，**状态泵每 tick
  一次**，与连接几只手柄无关；生命周期事件在同一 tick 内派发，移除不必等下一次扫描。
- **可观测性**：provider 暴露 `StateRefreshCount`；探针 `watch` 模式每 2 秒打印实际
  泵入速率——健康时应与监听间隔一致，若吸附在扫描间隔（约 4/s）即为本缺陷复现。

#### evdev 扫描不再卡采样（默认后端）

- **250 ms 重扫移出采样路径**：重扫原先在 `GetConnected()` 里持有同时守卫 `Poll`
  与事件应用的同一把锁，`/dev/input` 目录遍历（上百节点、每个 open 加若干 ioctl）
  会拖住 2 ms tick 与所有读取线程——摇杆移动一顿一顿即此形态。现在连接表是缓存，
  仅在设备集合变化时重建；首次之后的每次扫描都是单个后台任务，**列表锁只覆盖列表
  操作**，绝不跨越目录遍历与设备 I/O，每只手柄的 tracker 另有自己的锁。首次扫描按
  daemon 启动摘要的既有契约仍在调用线程内同步完成（仅此一次，也是唯一会把失败传给
  调用方的扫描）。
- **失败的扫描不拆设备**：列目录没能完成的扫描不再是“设备没了”的报告——它保留全部
  正在服务的设备、保留上一次发布的诊断，并把原因记录在新的 `LastScanError` 中；
  清除它的是下一次成功扫描。一次瞬时失败不再断开设备（以及它们按住的键）。

#### XInput／evdev → SDL3 保守配置迁移（初始实现）

- 首次为 SDL3 设备运行时，把旧后端（`xinput:N`／`/dev/input/eventN`）名下**用户
  自己的配置**复制到 `sdl:` 设备：**逐槽原样复制**（槽号不变，Leader 键、手势、
  临时层与特殊键随配置体一起过去），**旧文件只读不写**，新键写在旁边。
- **只覆盖空白**：仅当 SDL 设备的同号槽缺失、或可逐字段证明是未改动的库默认值
  （映射条目 ID 除外——库每次生成都换 GUID）时才复制；用户已在 SDL 下自定义的槽
  一律保留并说明。在早期 alpha 里已经开始配 SDL3 的用户不会被回填。
- **一对一才动**：旧配置设备与当前连接的 SDL 设备必须都恰为一个；多设备歧义时
  **整体跳过**并说明计数（运行时玩家索引是分配而非身份，不作为证据）。
- **布局反证跳过**：新旧设备都报告了具体但不同的布局时判定不是同一只手柄，拒绝
  迁移并记录该决定。
- **持久 marker 防复活／重置回滚**：配置目录根部 `legacy-migration.json`
  （`input-backend.json` 同一位置规则：在 profiles 目录之外）记录已处理配对；
  重连、重启、第二个窗口都不会二次复制——用户删掉的槽不会被重新填回，重置为默认
  的槽不会被旧配置悄悄替换。marker 损坏时按“无法证明任何配对是新的”处理，
  **宁可不迁移也不覆盖**。daemon 启动摘要逐条打印迁移与跳过原因
  （`legacy config migration: …`）。
- 边界：这是保守桥接而非完整迁移——只搬预设槽，不搬前台规则等全局状态；未实测
  多设备与真实旧配置组合，证据待补。

#### Windows 全局键盘捕获（编辑器捕获热键）

- 映射编辑器的“捕获键盘”在 Windows 上额外安装 **WH_KEYBOARD_LL 全局钩子**：
  其他程序用 `RegisterHotKey` 注册的相同组合键会在本应用被捕获并**抑制原动作**，
  不再“按下去先触发别人”。捕获完成规则与窗口路径一致：非修饰键按下记录目标，
  全部松开即结束；Esc 取消；修饰键不计为目标。
- **安全限制**：钩子只在捕获武装期间存在——失焦、打开设置、关闭编辑器、控件卸载
  都会立即结束捕获并卸载；安全桌面（UAC）与 Ctrl+Alt+Del 等系统序列无法捕获；
  注入事件（`IsInjected`）直接放过；卸载不在钩子回调内进行（可重入死锁），
  改为投递到 UI 线程执行；安装失败会明确结束捕获而不是让编辑器空等。
- 非 Windows 平台没有全局捕获，捕获提示如实说明“仅在本窗口聚焦时捕获键盘”。

#### 手柄劫持：按键直达映射卡片

- 劫持（会话级开关，每次启动默认关闭）开启期间，**新按下的按键直接打开该输入
  的映射配置**——选中与打开一步完成，并请求视图把该元素的卡片滚入可见；已有
  映射打开既有条目，没有映射开新草稿，不保存、不写配置。
- 摇杆偏转保持一级选中（模拟移动不是按键），**摇杆按压**作为按键同样直达；
  Guide 键仍专用于预设条的进入／退出。
- **关闭即失效**：关掉劫持，物理按键立即交还活动映射（注入租约解除），
  武装中的捕获一并结束，不写任何持久设置。

#### X11 两浮层真实 EWMH 置顶

- 临时层提示与屏幕键盘两个浮层在 X11 上按 EWMH 方式请求 `_NET_WM_STATE_ABOVE`：
  工具包的 `Topmost` 标志在映射前就已应用，窗口管理器不认；现在窗口存在后
  （每次显示，以及随后再一次）向管理器请求置顶。
- **保留其他 WM state**：读-改-写合并进 `_NET_WM_STATE` 现有列表
  （SKIP_TASKBAR 等原样保留），读不可信时绝不整属性覆写；同时发 EWMH 客户端消息
  并在自身栈内 raise。**不抢焦点**（不激活、不设 `_NET_ACTIVE_WINDOW`）、不动
  点击穿透区域、不命名其他窗口。
- Wayland（无 X11 句柄）、无 X 服务器、无 libX11 均为尽力而为：浮层保持原堆叠，
  不激活任何窗口。

#### Game Bar 两层分离、可恢复、卸载清理

- 设置页「Windows 手柄兼容性」拆成两层，各自独立：
  - **偏好层**：「关闭手柄唤起 Game Bar」写入并核验当前用户的控制器唤起偏好；
  - **静默处理程序层**：为本用户注册 `ms-gamebar:` 的 no-op 处理程序
    （`DeziroJoy.exe --noop-gamebar "%1"`），让链接有处理者而不是弹“选择应用”。
- **可恢复**：记录注册前的命令与归属标记；「恢复系统默认」还原此前的命令，
    此前没有则删除键。处理程序被其他程序接管（标记在、命令易主）时拒绝注册
    与恢复，不破坏对方。指向已不存在路径的陈旧注册可重新注册。
- **卸载清理**：卸载器在删文件前请已安装的应用交回注册
  （`--uninstall-gamebar-handler`）；可执行文件已缺失则跳过，卸载不因子进程
  退出码中断。仍可能残留时按设置卡或同一命令行手动恢复。
- **不保证**：两层都只覆盖各自机制——**不保证抑制所有弹窗**：部分 Windows 组件会以
  其他上下文触发同一对话框（实测在部分 Win11 LTSC 上存在），此时请用系统设置或
  安装／修复 Xbox Game Bar；不修改系统录制设置，ms-gamebar URI 之外的启动方式不主动拦截。

### 已知限制与验收边界

- SDL3 仍是显式实验选项：默认后端与 0.0.2 一致，provider 与探针未经真机验收；
  覆盖声明按 SDL 版本和能力记录。
- 旧配置迁移是**保守初始实现**：只搬预设槽、只在一对一且无反证时搬、marker 防
  二次复制；多设备歧义与布局反证按设计跳过。真实旧配置组合、多设备、Joy-Con
  形态的真机证据**待补**，S2 与 S3 均未完成。
- 全局键盘捕获仅 Windows；安全桌面与系统序列不可捕获属设计边界。
- X11 置顶为尽力而为：无视 EWMH 的管理器或不提供置顶语义的桌面可能不生效。
- Game Bar 两层均不保证抑制所有弹窗。
- 应用内自动更新按语义版本提供最新发布（含预发布）；`0.0.2-beta.3` 及更早版本
  的自动更新缺陷不变，从那些版本升级请手动下载。

### 升级与回退

- 升级不改变配置位置，不改写旧后端配置；未启用 SDL3 时默认后端不变
  （Windows 仍为 XInput，Linux 仍为 evdev）。
- 首次以 SDL3 连接时会按上述保守规则尝试一次迁移；**不切换到 SDL3 就不会发生
  任何迁移**；即使发生迁移，**用户已在 SDL3 下自定义的槽也不会被覆盖**。
- 回退：设置里切回平台默认后端，或重新安装 0.0.2；配置均保留。
- 完整说明见 [docs/SDL3-BACKEND.md](https://github.com/qiyuanhuakai/dezirojoy/blob/v0.0.5-alpha.2/docs/SDL3-BACKEND.md)。

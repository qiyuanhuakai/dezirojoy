# DeziroJoy Windows 真机 QA 检查清单

自动化测试覆盖引擎语义、平台映射与 GUI 结构；以下项目必须在 Windows 真机
连接真实手柄后人工验证。建议按顺序执行，每项记录实际结果。

## 1. 启动与连接

- [ ] `dotnet run --project src/DeziroJoy.App` 启动，窗口标题为 "Dezirojoy"（标题栏自定义，深色主题）
- [ ] 插入 Xbox 手柄，左侧"连接"卡片显示设备名（如 `Xbox 兼容手柄 #1`）与 "Xbox 布局"，状态点亮起
- [ ] 右侧手柄可视化器实时反映按键与摇杆位置
- [ ] 拔出手柄，状态点变灰、提示"未检测到手柄"，可视化器显示"未连接"

## 2. 默认映射（Xbox 布局）

启动映射后，逐项验证：

- [ ] 十字键 ↑ ↓ ← → 对应键盘方向键（可在记事本中输入验证）
- [ ] B → Enter
- [ ] A → Esc
- [ ] X → Ctrl+C（先选中一段文本）
- [ ] Y → Ctrl+V
- [ ] 右摇杆满幅推满，鼠标全屏移动；松开摇杆鼠标停止（无漂移）
- [ ] 左摇杆上推 = 页面向↑滚动；下推 = ↓；左右 = 水平滚动（支持水平滚轮的页面/Excel）
- [ ] 摇杆死区生效：轻微触碰不产生输入

## 3. 鼠标速度与精准度（核心差异化）

在"鼠标灵敏度"页：

- [ ] 拖动"最高速度"滑块，实时预览点的移动范围随之变化，与预期方向一致
- [ ] 速度以 px/s 表示；设为同一数值后，更换鼠标 DPI 或显示器，满幅速度表观一致
  （相对移动语义，与系统指针速度设置有关时需在系统设置中保持"提高指针精确度"关闭）
- [ ] 死区滑块：调到 0.4 后，中心 40% 范围内无移动；调回 0.15 恢复灵敏
- [ ] 响应曲线切换：线性 / 精准 / 激进 / 灵敏，预览图形与手感差异明显
- [ ] 平滑时间：0 = 即时跟随（有抖动感）；0.15s = 起步柔、极速仍可达
- [ ] 精准模式：按住左摇杆（L3），右摇杆鼠标速度降至约 35%，松手恢复
- [ ] 垂直反转勾选/取消，摇杆上推的鼠标方向随之反转
- [ ] 慢速微调：轻推摇杆 5%，鼠标以亚像素精度缓慢移动（不卡顿、不丢步）
- [ ] 点击"应用"后设置立即生效，无需重启

## 4. 映射编辑

- [ ] "添加映射"：LB → 单键 Space；编辑器面板出现，提交后列表 11 行
- [ ] "添加映射"：RB → 组合键 Ctrl+Shift+Z；提交后生效
- [ ] "添加映射"：左扳机 → 鼠标左键；按住 = 左键按下，松手 = 抬起
- [ ] 编辑 B 行改为单键 Space，原 Enter 行为消失
- [ ] 删除一行，列表减少一行且立即生效
- [ ] 取消勾选某行"启用"，该映射不再触发；重新勾选恢复

## 5. 配置持久化

- [ ] 修改若干映射后点击"保存配置"
- [ ] 完全退出程序，重新启动：配置仍在（读取 `%APPDATA%\DeziroJoy\profiles\`）
- [ ] "恢复默认"一键还原为内置 Xbox 默认配置
- [ ] 接入第二个不同型号手柄（如 PlayStation 手柄），各自使用独立配置互不干扰

## 6. 稳定性

- [ ] 连续映射 10 分钟无内存持续增长（任务管理器观察）
- [ ] 快速插拔手柄 5 次，程序不崩溃、状态正确恢复
- [ ] 映射运行中点击"停止映射"，所有按住的键/鼠标键被释放（不会卡键）
- [ ] 切到其他窗口（如游戏）后映射依然生效

## 7. 标题栏（仅 Windows 可见，Linux 上无法复现）

- [ ] 标题只出现一次，不与自绘文字或按钮重叠
- [ ] 只有"最小化"与"关闭"两个按钮（最大化已按反馈移除）
- [ ] 窗口仍可拖拽调整大小：四条边 + 四个斜角都要试
      （`WindowDecorations="None"` 会一并移除原生缩放边框，本项目以 8 个握柄补回；
       若此项失败，说明握柄层被破坏）

## 8. 主题

- [ ] 切换浅色/暗色，切换后重启仍记住选择
- [ ] 浅色下所有表面文字可读：主窗口、手柄模型、灵敏度面板、映射设置
- [ ] 暗色渲染与改造前一致（词元层对暗色是零行为变更）

## 9. 手柄模型与映射设置

- [ ] 模型上每个元素可点击：A/B/X/Y、十字键四向、双摇杆按压、LB/RB/LT/RT、Start/Back/Guide
- [ ] 按下物理按键，模型上对应元素高亮
- [ ] 点击元素即打开该元素的映射设置，"正在配置"显示的是刚点的那个
- [ ] 设置内直接按键盘：单键 → 单键目标；Ctrl+C → 组合键目标
- [ ] 设置内也可从分类列表选择，六个分类头可见
- [ ] Esc 取消、Enter 确认
- [ ] 已配置的元素在模型上有别于未配置的

## 10. 提权与常驻（UIPI 根因验证）

这是"置顶应用映射失效"的根因项，**必须单独验证**：

- [ ] 以管理员身份运行一个目标程序（如任务管理器、或一个提权的游戏），
      非提权状态下映射对它无效 → 复现原缺陷
- [ ] 通过界面"以管理员身份运行"重启程序，映射对同一提权目标生效 → 确认修复
- [ ] 界面显示当前是否已提权
- [ ] `--install-daemon` 注册登录时启动的提权任务，注销重新登录后 daemon 自动运行
- [ ] daemon 运行时 GUI 关闭，映射依然生效（这是 daemon 的意义）
- [ ] `--uninstall-daemon` 移除任务
- [ ] daemon 内存占用远低于 GUI（Linux 实测 49 MB vs 188 MB；Windows 应同量级）

若第 1 项不复现、或第 2 项仍无效，说明根因不是 UIPI，需要重新归因
（见 `docs/ELEVATION-AND-DAEMON.md`；另一种可能是目标程序校验
`RAWINPUTHEADER.hDevice`，那种情况提权无效，需要虚拟 HID 驱动）。

## 14. 实体按键直达配置与劫持

这一节的核心：按下实体键就能跳到那个键的配置，且配置期间按键不再被注入。

- [ ] 引擎**未启动**时，连接手柄后按下实体 A 键：编辑界面自动展开到 A 键的配置
- [ ] 引擎**已启动**时，同样按下 A 键：一样跳到 A 键配置，且**没有**触发 A 键的映射
  （若鼠标移动了/Enter 被输入了，说明劫持失效）
- [ ] 按下 B 键：编辑器切到 B 键；再按十字键左：切到十字键左
- [ ] 拨动摇杆：切到对应摇杆的配置
- [ ] 连接手柄时就已经按住的键**不会**跳转（只有按下沿才算一次触发）
- [ ] 长按不放：只跳转一次，不会连续跳转
- [ ] 正在编辑某项时，再次按下同一个键：保留未保存的修改，不刷新编辑器
- [ ] 编辑期间按下的键不注入；点"确定"或按 Esc 关闭编辑器后，映射立即恢复注入
- [ ] 编辑器里点"捕获键盘"后，此时按实体手柄键：**不**跳转（键盘捕获优先）
- [ ] 手柄模型上的实时高亮与导航同时工作（按下哪个键，模型上哪个键亮）

## 15. 手势：双击与长按

- [ ] 只配了单击的按键：手感与 alpha.1 一致（零延迟，不应有可感知的迟滞）
- [ ] 配了双击的按键：快速按两次触发双击动作；单击慢按不触发
- [ ] 配了长按的按键：按住到设定时长才触发；短按不触发
- [ ] 长按 + 连续重复：按住不放按设定间隔重复触发（像电脑上长按方向键）
- [ ] 没有配双击/长按的按键完全不引入等待——这是延迟规则的验收点，
  用"只配单击的键"和"配了长按的键"对比按下的响应速度
- [ ] 摇杆配键盘动作时，方向选择器出现且可选（上/下/左/右）
- [ ] 按键配鼠标移动时，同样出现方向选择器

- [ ] 配置界面：点模型上的键，该键高亮并有一条线连到编辑器，编辑器在原地展开

- [ ] 拖动条：填充部分与未填充部分颜色区分明显，滑块为圆形，拖动时有数值读数
- [ ] 浅色/深色两套主题下，卡片圆角、拖动条、连接线都正常
- [ ] 侧栏"外观" radios 能切换主题，与标题栏明月图标行为一致
- [ ] 侧栏"后台服务"卡片：安装/卸载/刷新可用，状态文字与第 10 节一致

## 已知限制（预期行为，非缺陷）

- XInput 无法提供稳定硬件 ID，配置按 XInput 槽位（#1-#4）保存；
  两个手柄互换插槽时，配置随槽位而非硬件走
- 仅支持 XInput 兼容手柄（覆盖绝大多数 Xbox/第三方手柄）
- 需要 Windows 8+（XInput 1.4）
- Windows 上 SendInput 受 UIPI 约束：非提权进程无法向提权目标注入输入，
  且失败时错误码不指明源于 UIPI。必须提权运行
- daemon 输出目前只写 stdout；计划任务方式运行时需要重定向或未来的日志文件

## 17. 手柄休眠

无线手柄在**无用户输入 15 分钟**后会自动关机。该计时器在手柄固件内，
Windows 没有任何公开 API 可以禁用它或重置它，因此本应用**不提供"保持唤醒"开关**——
做一个实际无效的选项比不提供更糟。

- [ ] 连接手柄后拔掉/休眠，状态栏应显示"手柄已断开连接，可能已进入休眠，
      请按手柄电源键唤醒"，而不是"未检测到手柄，请连接手柄"
- [ ] 若之前从未连接过手柄，状态栏仍显示"未检测到手柄，请连接手柄"
- [ ] daemon 形态下上述两条同样成立：断开文案来自 daemon 快照的存在性翻转，
      未连接文案来自快照从未报告过手柄

已验证无效、故未采用的方案（均有官方文档依据）：

| 方案 | 结论 |
| --- | --- |
| `SetThreadExecutionState` / `PowerCreateRequest` | 文档明确只作用于**系统/显示器**空闲计时器，无一处提及外设，对手柄无效 |
| `XInputSetState(0,0)` 周期性调用 | 民间做法。零值确实会送达设备（`XInputEnable` 文档："even if it is 0"），但是否重置计时器无任何文档依据；PPSSPP、Dolphin、RPCS3、SDL、xenia、x360ce 全部调用 `XInputSetState`，无一实现保活循环 |
| GIP Set Device State = Full power | 微软自家协议规范 MS-GIPUSB 中唯一记录能重置计时器的命令，但**无公开 API 可发送**（微软对开发者的答复："we don't have any public way for an application to send them"） |
| 未公开 IOCTL（`xboxgip.sys` 0x40001C4C） | 需 SYSTEM 权限、仅 USB、完全未公开，不适合普通用户态应用 |

唯一可靠的办法：**用 USB 线连接**。MS-GIPUSB 原文：该计时器
"Not relevant to USB wired-only devices"。

同理，软件也无法唤醒已休眠的手柄——检测到断开时只能提示用户按电源键。

## 18. Alt+Tab 与瞬时掉线（本轮修复）

**症状**：按住映射为 Alt 的手柄键、再点按映射为 Tab 的键，切换器
每次都回到 MRU 第一个窗口，无法连续切换。键盘操作正常；关闭应用窗口
后手柄操作也正常。

**根因**（已定位并修复，提交 225d5e8）：引擎每 tick（2ms）都按
`GetConnected()` 重建运行时表，而 `XInputGetState` 在蓝牙手柄上会瞬时
失败。一次失败就让设备从列表消失 → `Remove()` → `ReleaseAll()` 抬起
正在按住的所有键（包括 Alt）→ 切换器关闭；下一个 tick 设备回来，
引擎重新按下 Alt → 切换器从第 1 位重开。键盘不经过这条链所以正常；
关闭窗口后引擎停止轮询所以也正常。

**修复**：设备必须连续缺席 5 个 tick（2ms 节拍下即 10ms）才真正移除。
UI 的存在性路径（`RefreshPresence` / `SamplePresence`，300ms 节拍）
故意不享受宽限——那里 5 tick 等于 1.5 秒，且引擎停止时没有任何键被按住。

**真机验证步骤**：

1. 将某手柄键映射为 Alt，另一键映射为 Tab
2. 启动映射，按住 Alt，连续点按 Tab 五次
3. 预期：切换器逐窗前进，能到达第 5 个窗口；松手后落在最后选中的窗口
4. 若仍跳回第一个窗口，说明瞬时掉线的频率超出了 10ms 宽限，
   需要提高 `EngineHost.DeviceAbsenceGraceTicks`

**补充观察**：daemon 退出时会打印 `injected: N events · M blocked`
（提交 026c641）。若此处 blocked 非零，说明注入被 UIPI 丢弃，
那是提权问题而非本缺陷。

  断线会释放旧租约，daemon 存活或重启后的重连都必须恢复租约且不改变用户暂停状态。
- 真实 X11：深色/浅色设置面板在 1180×780、1400×900、1920×1080 均完成打开/关闭；
  Ctrl+1/2/3、Ctrl+,、侧栏收起/恢复、模型点击、捕获期快捷键抑制及两段 Escape 均通过。
- Windows 提权链路：普通权限客户端连接 high-integrity daemon，Start/Stop 均为 Accepted；
  独立的提权注入探针向提权 WinForms 目标发送 Enter，目标日志收到 KEYDOWN/KEYUP Return，
  SendInput 失败计数为 0。测试 daemon、目标和探针均已清理，用户原有 GUI 保持运行。

## 已知限制（预期行为，非缺陷）

- XInput 无法提供稳定硬件 ID，配置按 XInput 槽位（#1-#4）保存；
  两个手柄互换插槽时，配置随槽位而非硬件走
- XInput 只能看到 Xbox 布局的标准按键（14 个）。超出该布局的按键
  （部分第三方手柄的宏键、背拨片）在 Windows 上不会被识别。
  已实测确认（蓝牙 Xbox 无线手柄，VID 045E / PID 0B13）：该手柄唯一的
  HID 实例是带 `IG_` 标记的 XInput 虚拟副本，能读到报告描述符但
  `HidD_GetInputReport` 返回 ERROR_INVALID_PARAMETER、`HidD_GetFeature`
  返回 ERROR_INVALID_FUNCTION、阻塞读零报告——即该接口不承载输入，
  额外按键根本不在其中。读取这类按键需要自写过滤驱动（Steam / ReWASD
  的做法），应用层无解
- Linux 上 evdev 走 raw-code 通道，可以识别
- 需要 Windows 8+（XInput 1.4）
- Windows 上 SendInput 受 UIPI 约束：非提权进程无法向提权目标注入输入，
  且失败时错误码不指明源于 UIPI。必须提权运行
- daemon 输出目前只写 stdout；计划任务方式运行时需要重定向或未来的日志文件

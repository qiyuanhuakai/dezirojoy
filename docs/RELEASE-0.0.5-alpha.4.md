## DeziroJoy v0.0.5-alpha.4

本版是 SDL3 统一输入后端的第四个 alpha：通用控件面板的响应式布局与遮挡修复、NS 字形、
DInput 设备真实识别、daemon 全平台失联恢复，以及性能实验 **P1–P4** 的设置与实现落地。
默认输入后端仍为 XInput／evdev，SDL3 仍是设置中的显式实验选项；S3 默认切换未开始。

alpha.1–alpha.3 的交付（SDL3 provider、探针、保守迁移、映射补充、U1／U2、更新
watchdog 等）继续有效，详见各自发布说明，此处不再重复。

### 本版更新

#### 通用面板：响应式布局、不遮挡、连线到通用卡片

- 通用控件面板改为**响应式布局**：五个分区同处一个滚动区，“更多输入”栏固定在其下方——
  声明很长的设备滚动而不是把栏推出视野；窄舞台时卡片**换行而不是互相重叠**；每张卡片
  等宽，分区读作匀整网格。
- 卡片的隐藏按钮占**固定 16px 预留列**（无论显示与否），不再抢夺卡片宽度或压在卡片上；
  设备自带的长标签（如“Back / Select”）在卡内换行并省略，不越界、不压邻卡。
- 编辑器 lift／zoom（含命中测试）同样作用于面板；劫持跳转的“滚入可见”与连线在虚拟化
  列表下继续工作（`ScrollIntoView` 先实现卡片再滚动）。

#### 编辑区增高

- 编辑器打开时舞台行从 420 缩到 250，把高度真正让给编辑器卡片（与模型 0.65 缩放、
  lift 组合）；关闭后恢复。

#### NS 字形

- 设备可提供面键字形时（SDL 读取的 Nintendo Switch 字形），固定布局的表面按设备自己的
  字形**重新标注**——NS 手柄物理 X 在逻辑 Y 位，Xbox 字母绘图会点亮错误的字母；重新标注
  只改显示，**逻辑位置与映射语义不变**（同一份配置在不同手柄上含义一致）。读不到字形时
  回退逻辑名（A／B／X／Y 是 Core 自己的方位名），不猜品牌字形。

#### DInput 设备真实识别

- SDL 3.4.20 起 `SDL_AddGamepadMapping` **立即重新评估**已连接（含此前已枚举）的
  joystick：`map` 流程保存后通过 SDL 自己的 GUID 查询当场确认映射**已注册且已生效**，
  用户不再只能靠重启试错。
- 需要重启的是 **daemon**（它只在启动时读一次 `sdl-mappings.json`），不是 SDL：因此
  映射要进入实际映射路径仍按提示**重启常驻服务**；探针进程自身已认新映射。

#### daemon 全平台失联恢复

- 设置页（daemon 模式）新增「**重新连接守护**」：先做轻量客户端重连；已连接但不应答时
  以 3 秒存活探测证伪（管道接受连接却永不完成请求的状态从此有用），随后进入**监督重启**。
- 监督重启的每个阶段有界且逐条报告：停常驻服务（Linux systemd 用户单元／Windows 计划
  任务）→ **按身份确认结束**旧 daemon（PID＋启动时间，复用 PID 绝不误杀）→ 释放映射通道
  与注入槽位 → 经计划任务／用户单元启动替代进程；随后客户端对替代进程重新握手。
- **Windows 提权无计划任务回退**：daemon 以本进程没有的令牌运行（提权且未装计划任务）
  时，监督者把已确认身份交给**本程序的提权副本**（`runas`，仅传 PID 与存活时刻），由它
  用自己的令牌复核身份、结束旧 daemon、等待槽位并成为替代进程——不是盲目 kill，也不在
  其旁另起进程。UAC 被拒绝时给出明确失败与出路（“请在提权提示中允许，或以管理员身份
  运行后重试”），不假装恢复。
- 恢复报告（成功与否、经过的阶段、失败原因）展示在同一按钮处；一次只允许一个监督重启。

#### P1：Software 渲染设置（实验）

- 设置页「界面渲染（仅 Windows）」：默认「平台检测」（Windows 上优先 AngleEgl，失败
  回退软件渲染），可选「软件渲染 Software（实验）」——把 Win32 后端钉为仅 CPU 渲染。
- 设置持久化；临时覆盖：环境变量 `DEZIROJOY_RENDER=software|default` 或
  `--render=software|default` 启动参数（命令行 > 环境变量 > 持久化 > 默认）。无法识别的
  取值按默认启动并说明原因；非 Windows 上开关无效并如实报告。daemon 与无头路径从不读取
  它。**Software 无法初始化时应用启动失败，不静默回退**。保存后重启主程序生效。
- **A/B 证据（WSL 内的 Windows 实测，见下）**：默认约 283–289 MiB WS／185–191 MiB
  私有，Software 约 163–165 MiB WS／75–77 MiB 私有，CPU 未上升。设置有效；**交互
  （动画流畅度、输入到画面）仍建议真机复验**。

#### P2：不可见预览停止更新

- 灵敏度预览 tick 增加门控：对应 Tab 不可见、窗口隐藏／失焦／最小化、面板已静止
  （无校准采集、预览点回中、速度衰减到零、手柄在休息）时停更；仍在变化的（实时扫动、
  点仍在滑行、校准采集中、手柄刚离开休息）继续绘制。只作用于 UI 预览，不影响 daemon
  映射与输入释放。

#### P3：合并输入样本的 UI 分发

- daemon 输入样本改由 16 ms UI 帧时钟驱动：每设备只保留最新样本，每 UI 帧合帧分发一次
  （到达序在合帧内保持，设备作用域读取仍然正确）；校准等需要完整样本流的功能继续走
  独立、无损的逐样本路径。

#### P4：惰性创建、虚拟化与订阅生命周期

- 重表面（设置浮层、映射编辑器、灵敏度面板）首次打开才构建，关闭即释放（DataContext
  清除，绑定与代码后置订阅随之释放）——反复开关只留下打开着的那个，不按访问次数堆积。
- 映射卡片列表虚拟化：只实现可见卡片；劫持跳转的滚入可见经 `ScrollIntoView` 适配。
- 列表与浮层的订阅随可视化树采纳／释放：关闭窗口不再继续应答请求，重建窗口不再叠加
  第二份订阅（生命周期由测试钉住）。

### 性能证据（如实记录）

- **P1**：在 WSL 内的 Windows 上实测（同机同场景、交替运行）：默认渲染约
  **283–289 MiB 工作集／185–191 MiB 私有字节**，Software 约 **163–165 MiB 工作集／
  75–77 MiB 私有字节**；CPU 未上升。因此 P1 的**设置与其内存效应有效**，但流畅度与
  兼容性代价**建议在真实 Windows 机器上复验**后再决定是否默认切换。
- **P2–P4**：目前只有自动化测试与生命周期验证（门控条件、合帧、惰性释放、订阅不堆
  积），**尚无有效的独立 A／B 数据**；本版不把任何收益写成事实。
- **问题现场参考**：当前托盘进程约 **208 MiB 工作集／157 MiB 私有字节**——这是需要
  优化的现场口径，与上述测试环境（WSL 内的 Windows、虚拟手柄场景）**不可直接比较**。

### 已知限制与验收边界

- SDL3 仍是显式实验选项；S2 验收未完成（迁移与映射补充的真机／多设备证据、Joy-Con
  规则、完整生命周期待补），S3 未实施；U1／U2 已实现但真实未知型号设备待复验。
- 映射补充只覆盖用户实际映射过的设备；`map` 保存后 SDL 立即认账，但 daemon 需重启
  常驻服务才进入映射路径。
- daemon 失联恢复的有界重试不能保证救回每一个失联 daemon；UAC 被拒、身份无法确认、
  槽位被占等失败会逐阶段报告，不谎报成功。
- P1 仅 Windows 有效；Software 初始化失败会导致启动失败（设计选择，非缺陷）。
- P2–P4 无有效 A／B 前，不宣称 CPU／内存／流畅度收益；性能结论以复跑数据为准。
- Game Bar 两层均不保证抑制所有弹窗（实测部分 Win11 LTSC 仍可能弹窗）。
- 应用内自动更新按语义版本提供最新发布（含预发布）；`0.0.2-beta.3` 及更早版本
  的自动更新缺陷不变，从那些版本升级请手动下载。

### 升级与回退

- 升级不改变配置位置，不改写旧后端配置；未启用 SDL3 时默认后端不变。
- 渲染设置、输入后端选择都是持久化偏好：改回默认选项即恢复原行为；配置均保留。
- 回退：设置里切回平台默认后端／默认渲染，或重新安装 0.0.2；配置均保留。
- 完整说明见 [docs/SDL3-BACKEND.md](https://github.com/qiyuanhuakai/dezirojoy/blob/v0.0.5-alpha.4/docs/SDL3-BACKEND.md)。

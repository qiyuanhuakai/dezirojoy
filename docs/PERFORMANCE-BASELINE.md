# Windows 后台架构性能基线

> 测量方式：provider 层虚拟手柄 + 真实墙钟循环、引擎、IPC、三进程与 Windows `SendInput`。
> 这不是物理手柄端到端验收，也不证明相对旧版本“手感更稳定”。

## 结论摘要

- 无手柄且 GUI 退出时，daemon 平均 CPU 为 **1.48% 单核**，呈现宿主为 **1.32%**；两者合计工作集平均为 **177.95 MiB**，私有字节平均为 **71.92 MiB**。常驻内存主要在呈现宿主，而不是 daemon。
- 持续鼠标且 GUI 退出时，合计 CPU 为 **5.75% 单核**，合计工作集平均为 **185.50 MiB**；打开 GUI 后分别为 **17.67%** 和 **545.45 MiB**。GUI 打开成本明显，但 GUI 退出后其进程不常驻。
- 代码目标 Tick 间隔为 2 ms，但实测无手柄 Tick p50 为 **15.52 ms**，持续鼠标为 **14.17 ms**，p95 为 **16.00 ms**。因此不能把目标间隔写成实际调度间隔。
- 本矩阵记录 **62081 次成功 SendInput、0 次失败**。持续鼠标场景 Poll→首个 SendInput 返回的 p95 为 **1.63 ms**；该指标不含物理输入送达与目标应用处理时间。
- 120 秒连续鼠标场景中，daemon 工作集从 **58.38→70.62 MiB**，私有字节从 **21.21→31.63 MiB**。这是需要延长观测和定位的增长信号，不能写成“无内存增长”。
- 本报告是当前机器、当前工作区构建的一组可复跑基线，不是跨设备性能承诺。现有数据可以约束后续回归，但不足以宣称已证明“后台轻量”或“手感更稳定”。

## 未覆盖边界

1. 没有物理手柄，因此不测蓝牙／USB／XInput 输入送达、断连重连和休眠恢复。
2. 延迟止于 `SendInput` 返回，不测目标应用接收、处理或画面呈现，不是端到端手感延迟。
3. 不测普通应用与管理员应用的注入差异；daemon 与采集器同为非提权进程。
4. 不做旧版本对照，因此不能证明“更稳定”；120 秒连续运行也不替代长时间挂机与泄漏验收。
5. GUI 开关段使用进程终止，不覆盖用户点击关闭时的优雅清理；多屏、缩放、焦点与浮层位置仍属真机验收。
